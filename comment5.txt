## Golden Solution Approach

Both trials report the same reference implementation (no discrepancy):

1. **Data source**: Python reads the SQLite database via `sqlite3`.
2. **BOM explosion**: BFS/topological order ("low-level code" pattern), accumulating cross-path demand into a `needed_parts` dict before performing any manufacturing step at a given level.
3. **Stock netting**: At each BOM node, consume available on-hand stock first; net-build quantity rounded up to batch_size multiple.
4. **Scrap formula**: child demand = `ceil(build_qty × qty_per × (1 + scrap_pct/100)) + setup_scrap_qty`.
5. **Substitutes**: coverage via floor division of available substitute stock, ranked by preference.
6. **Workcenter capacity**: setup + per-unit hours deducted from available capacity.
7. **Limiting resource**: `argmin(available/required)` computed independently per leaf part (including substitute coverage) and per workcenter, evaluated from the order's **initial** resource state (frozen `curr_inv`), not consuming state across leaves.
8. **Output**: orders sorted by `order_id` ascending; priority processing by score then `order_id DESC` as tie-breaker.

**task__wTDZj6t — approach_validity FAIL**: This trial surfaces a genuine task/verifier problem:

- **BFS vs DFS**: `instruction.md` says "Explode the product's BOM top-down through all assembly levels. At each node, consume available on-hand stock of that part first." Sequential mutation of the initial state is a plausible implementation.

Both failures in task__wTDZj6t arise from the agent following instruction-permitted approaches that the verifier silently rejects via undisclosed conventions. This is a **task/verifier problem**: the BFS requirement for shared-node demand aggregation is an implicit MRP domain convention that should be explicitly documented in `instruction.md`.
